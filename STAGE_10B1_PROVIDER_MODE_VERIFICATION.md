## 3. Two-Factor Authentication (2FA) Security Integrity

### 3.1 Separation of Convenience from Security
In the local demo walkthrough, the 6-digit OTP code (`123456`) is detected from the outbound simulated WhatsApp chat and pre-filled into the console OTP field to streamline presentation flow.

### 3.2 Visual Disclaimers & Operator Approval Gate
1. **Pre-fill Disclaimer**: The UI dynamically attaches a prominent badge and notice:
   > `[SIMULATED DEMO CONVENIENCE — NOT PRODUCTION 2FA] In production, OTP is received on the passenger or operator device and must be manually entered. Auto-prefill is provided solely for demonstration fluidity.`
2. **Mandatory Authorization Gate**: Entering or pre-filling an OTP **never** authorizes or executes a transaction by itself. Rebooking execution requires explicit authenticated operator action (`POST /api/cases/{id}/approve` with `ROLE_ADMIN` or `ROLE_SUPERVISOR`). Unapproved rebooking attempts are rejected with `HTTP 403 Forbidden`.
