# Stage 14 — API Contract Changes & Error State Specifications

## Overview
Stage 14 establishes deterministic REST API behaviors, enhanced request headers for distributed idempotency, structured error response formats, and fail-closed security transitions across all passenger and operator endpoints.

---

## Distributed Idempotency Headers
All mutation endpoints (booking simulation, option generation, human approval, and rebooking execution) now support explicit client idempotency keys via HTTP headers.

| Header Name | Type | Description | Behavior on Duplicate |
| :--- | :--- | :--- | :--- |
| `X-Idempotency-Key` | String (UUID / custom) | Unique transaction token generated by client | Returns existing cached HTTP response or 409 Conflict if in-progress |
| `X-Tenant-Id` | String | Multi-tenant isolation partition identifier | Defaults to `tenant_default` if omitted |

## State Machine Transition Contract

### Legal Transitions
```
DETECTED -> OPTIONS_READY | ESCALATED | DATA_RECONCILIATION_REQUIRED
OPTIONS_READY -> AWAITING_OPTION_SELECTION | OPTION_SELECTED | ESCALATED | DATA_RECONCILIATION_REQUIRED
OPTION_SELECTED -> REVALIDATING_OPTION | AWAITING_PASSENGER_CONFIRMATION | AWAITING_PASSENGER_OTP | ESCALATED | DATA_RECONCILIATION_REQUIRED
AWAITING_PASSENGER_OTP -> PASSENGER_VERIFIED | OTP_FAILED | OTP_EXPIRED | LOCKED_OUT | ABANDONED | DATA_RECONCILIATION_REQUIRED
PASSENGER_VERIFIED -> REBOOKING | APPROVED | DATA_RECONCILIATION_REQUIRED
APPROVED -> REBOOKING | REVALIDATING_OPTION | ESCALATED | DATA_RECONCILIATION_REQUIRED
REBOOKING -> PENDING_PROVIDER_SUBMISSION | PROVIDER_CONFIRMED | PROVIDER_OUTCOME_UNKNOWN | BOOKING_FAILED | EXECUTION_FAILED | DATA_RECONCILIATION_REQUIRED
PENDING_PROVIDER_SUBMISSION -> PROVIDER_CONFIRMED | PROVIDER_OUTCOME_UNKNOWN | EXECUTION_FAILED
PROVIDER_OUTCOME_UNKNOWN -> RECONCILING | DATA_RECONCILIATION_REQUIRED | BOOKING_FAILED
RECONCILING -> VERIFYING_BOOKING | DONE | BOOKING_FAILED | DATA_RECONCILIATION_REQUIRED
PROVIDER_CONFIRMED -> VERIFYING_BOOKING | PAYMENT_AUTH_PENDING | DONE
VERIFYING_BOOKING -> VERIFYING_TICKET | DONE | DATA_RECONCILIATION_REQUIRED
VERIFYING_TICKET -> DONE | DATA_RECONCILIATION_REQUIRED
DONE -> DATA_RECONCILIATION_REQUIRED (Upon post-completion audit finding)
```

### Prohibited / Guarded Transitions
- Transition to `APPROVED` or `REBOOKING` from `ABANDONED` $\rightarrow$ **409 Conflict**.
- Transition to `APPROVED` or `REBOOKING` from `EXPIRED` $\rightarrow$ **409 Conflict**.
- Transition to `APPROVED` on `ESCALATED` case $\rightarrow$ **409 Conflict**.
- Rebooking execution without `APPROVED` or `PASSENGER_VERIFIED` state $\rightarrow$ **403 Forbidden**.
- Submitting rebooking when another rebook execution is currently `IN_PROGRESS` $\rightarrow$ **409 Conflict**.
- Transition out of `DATA_RECONCILIATION_REQUIRED` without authoritative manual desk resolution $\rightarrow$ **409 Conflict**.

## API Endpoint Specifications

### 1. `POST /api/cases/{caseId}/rebook`
- **Request**: Empty body or JSON rebooking parameters.
- **Success Response (200 OK)**:
  ```json
  {
    "id": "C1",
    "bookingId": "B1",
    "passengerName": "Ananya Sharma",
    "state": "DONE",
    "flight": "FL301",
    "newPnr": "R7X2K9",
    "providerReconciliationStatus": "RESOLVED_CONFIRMED",
    "providerOrderId": "ORD-R7X2K9",
    "approvedOptionId": "O2"
  }
  ```
- **Concurrency Conflict (409 Conflict)**:
  ```json
  {
    "status": 409,
    "error": "Conflict",
    "message": "Rebooking execution currently in-progress for case C1. Distributed idempotency lock acquired by worker 48c821.",
    "idempotencyKey": "REBOOK_EXECUTION:C1"
  }
  ```
- **Provider Timeout / Outcome Unknown (200 OK - Reconciled Fail-Safe)**:
  ```json
  {
    "id": "CASE-ST14-TIMEOUT",
    "state": "BOOKING_FAILED",
    "providerReconciliationStatus": "RESOLVED_NOT_CREATED",
    "error": "Rebooking timed out. Host inquiry confirmed no duplicate ticket was created."
  }
  ```

### 2. `POST /api/cases/{caseId}/verify-otp`
- **Request**:
  ```json
  {
    "phone": "+919876543210",
    "otp": "839201",
    "optionId": "O2"
  }
  ```
- **Lockout Response (423 Locked / 400 Bad Request)**:
  ```json
  {
    "status": 423,
    "error": "Locked",
    "message": "Phone +919876543210 is temporarily locked out due to exceeding maximum failed verification attempts (3). Try again after 15 minutes.",
    "lockoutExpiresAt": "2026-11-11T11:45:00"
  }
  ```
- **Single-Use Replay Rejection (400 Bad Request)**:
  ```json
  {
    "status": 400,
    "error": "Bad Request",
    "message": "OTP challenge has already been consumed or has expired."
  }
  ```
