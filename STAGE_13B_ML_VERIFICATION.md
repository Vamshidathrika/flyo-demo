## 1. Exit Code 2 Post-Mortem & Root Cause Analysis

During previous verification, invoking `pytest ml/tests` resulted in an immediate failure with exit code 2. A forensic investigation was conducted to identify the exact cause:

### Root Cause
1. **Global Interpreter Environment Drift:**  
   The execution command invoked Homebrew's global Python 3.11 binary (`/opt/homebrew/bin/pytest`), which lacked dependencies specified in `ml/requirements.txt`—notably `pandas`, `scipy`, and `shap`.
2. **Collection Error Trigger:**  
   When pytest attempted to discover tests in `ml/tests/test_models.py` and `ml/tests/test_monitoring.py`, the interpreter threw:
   - `ModuleNotFoundError: No module named 'pandas'`
   - `ModuleNotFoundError: No module named 'scipy'`
   - `ModuleNotFoundError: No module named 'shap'` (imported in `ml/service/explainability.py`)
   In accordance with pytest exit code specifications, collection errors immediately terminate the runner with **Exit Code 2** without executing a single test case.

---

## 2. Engineering Remediation

1. **Dedicated Isolated Virtual Environment (`ml/.venv`):**  
   Initialized a dedicated, reproducible virtual environment using Python 3.11.15:
   ```bash
   /opt/homebrew/opt/python@3.11/bin/python3.11 -m venv ml/.venv
   ```
2. **Full Dependency Provisioning:**  
   Installed all production dependencies from `ml/requirements.txt` alongside `shap` and `pytest`:
   - `fastapi 0.162.2` & `uvicorn 0.54.0`
   - `pydantic 2.14.3`
   - `numpy 2.4.6`, `pandas 3.1.1`, `scipy 1.17.1`
   - `scikit-learn 1.9.1`, `xgboost 3.2.0`
   - `shap 0.51.0` (with `numba` and `llvmlite`)
   - `joblib 1.6.0`, `httpx 0.28.1`, `pytest 9.2.0`
3. **Requirement File Pinned:**  
   Updated `ml/requirements.txt` to explicitly mandate `shap>=0.45.0` and `scipy>=1.13.0`.
